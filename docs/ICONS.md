# Icons

The web UI draws its icons from one generated, vendored subset. Nothing is fetched at runtime (no CDN, the CSP is unchanged) and no icon is ever built through HTML parsing: `svgIcon` creates each element with `createElementNS`.

## What ships

- `internal/web/static/icons.js` holds only the glyphs the page uses, as flat shape lists (`ICON_SET`), never the whole libraries. It is generated by `tools/iconsgen` and must not be edited by hand.
- `tools/iconsgen/names.txt` is the list of names (sorted, one per line; a `si:` prefix is a Simple Icons mark, any other name is a Lucide outline).
- `internal/web/static/iconmap.js` maps concepts (an action, a status, a kind of resource) to those names, so one concept always gets one glyph.
- A jstest checks that the set holds exactly the names the page uses.

## Regenerating

Get the two tarballs and check them against the integrity values above:

```sh
npm pack lucide-static@1.70.0 simple-icons@16.37.0
npm view lucide-static@1.70.0 dist.integrity
npm view simple-icons@16.37.0 dist.integrity
```

Extract each into its own empty directory (the SVGs are under `package/icons`), then from the repo root:

```sh
go run ./tools/iconsgen -names tools/iconsgen/names.txt \
  -lucide <lucide dir>/package/icons -lucide-version 1.70.0 -lucide-integrity sha512-A9UgY98g94IuHQY7rl7/AFwHX7T1qNpzryim+Kw5CGhdV2STobtBY+ib/Z44ohyqXEJB88gvXFAeJ87uOOHKLw== \
  -si <simple-icons dir>/package/icons -si-version 16.37.0 -si-integrity sha512-8mCJIhpMYOL9g13GW59EiL3sVXJnTEKGCTZFaekl9UQ3Qo0SwVjnLaJ82QiaH8BKBdouEDzrHMXIWh8cBIy48A== \
  -o internal/web/static/icons.js
```

To add an icon, add its name to `names.txt` (keep it sorted), use it in `iconmap.js` or a `uiIcon("…")` call, and regenerate. The generator refuses a glyph that uses an element or attribute outside its allowlist.
