# Features

Every feature in detail. The [README](../README.md) has the one-line summary.

## Watch

- **Multi-session web terminal.** Run several agent sessions side by side in the browser (xterm.js over WebSocket), on desktop or phone. A plain drag over Claude Code's fullscreen view copies the text: the agent's clipboard write (OSC 52) is accepted only within 1.5 seconds of you releasing a click or drag, or pressing Ctrl+C, in that terminal, while it is visible and focused, and never while the session's earlier output is still being replayed after a reconnect. Each copy shows a toast with the number of lines. Text with a bare carriage return, a line or paragraph separator, or a Unicode format character (text-direction controls, zero-width spaces and joiners, tag characters) is refused with a warning, because pasted into a shell it could run something the screen never showed; Shift+drag (Option+drag on macOS) still copies it, emoji sequences joined by a zero-width joiner included. A request to read your clipboard is never answered. Shift+drag (Option+drag on macOS) still selects with the terminal's own selection.
- **Attention awareness.** Sessions report whether they are working, idle or waiting, and why: a pending tool call or permission prompt, or simply your turn. The tab title and favicon change while something needs you. For Claude Code sessions, a card shows the pending tool call.
- **Usage and cost.** Per-session context size and model, and account-level 5-hour and 7-day rate-limit windows when a statusLine hook provides them. A local analytics store (SQLite) ingests Claude Code transcripts into daily token usage, estimated cost per model, project and session, and skill/MCP attribution. Dollar figures are estimates from a built-in price table. Analytics can be turned off.
- **Environment badge.** `env_label` and `env_color` mark an instance as DEV, PROD and so on in the UI.

## Run and steer

- **Session persistence.** Agents run under [abduco](https://www.brain-dump.org/projects/abduco/), so they survive a restart of the CuliBox daemon. On restart, CuliBox re-attaches. Closing the browser or the terminal that runs `culibox serve` does not kill sessions.
- **Steer from the UI.** Interrupt a session, restart an exited one (Claude Code sessions on the host tier resume the same conversation), and, if `"replies_enabled": true` is set in config.json (off by default; restart to apply), answer permission prompts or send a one-line reply from the needs-you card. This is limited to Claude Code sessions.
- **Profiles.** Create profiles in the UI (Settings › Profiles), or define agents in the config file; either way they carry launch options (flags and env vars) as toggles on the spawn form. A quick-shell profile is detected from `$SHELL`. A save made from a stale editor is refused, so an older tab or another device cannot overwrite a newer change.
- **Files dock (desktop).** Browse, search, edit, upload, and download folders as an archive, with size and file-count caps. The dock opens from a pane's Files button or Ctrl+Shift+E (Cmd+Shift+E on macOS), and it pushes the panes aside instead of covering them. It is a column to the right of the panes, whether there is one pane or several, and it shows the focused pane's session; with several panes, a pin keeps it on one session while you move focus. Each session keeps its own open files, and the dock reopens after a page reload if it was open. Every way of opening a file goes to the dock: the tree, a file path in a terminal (with its line number), the palette, a git badge. There is no "Open in pane".
- **Tabs and the file tree.** Each session has a strip of tabs, with a breadcrumb row above the file showing its path and, when the agent changed it, "Edited by" the session and how long ago. A single click opens a preview tab (in italics) that the next single click replaces; a double-click or an edit keeps it. The explorer is a tree with a Go to file box (Ctrl+P), New file, and a menu for New folder, Upload, Refresh and Collapse all. It follows the text-size setting in Settings.
- **Editor.** Files open in one Monaco editor (the editor inside VS Code), shared by the dock's tabs and always editable: there is no Edit button. Saving is manual, Ctrl+S (Cmd+S on macOS). A dot on the tab and an "Unsaved" note under the breadcrumbs mark a buffer that differs from the file. A file the editor will not save is locked, with the reason under the breadcrumbs: a file inside a session's box, a folder the server never writes to, a text file that is not UTF-8 (saving it would change its bytes, and the status bar says "Not UTF-8"), or something that is not plain text. Monaco is bundled in the CuliBox binary and loads the first time you open a file, never from a CDN.
- **When the agent writes a file you have open.** While the file is on screen, CuliBox checks it every two seconds. A file you have not edited reloads by itself, and the reload clears its undo history. A file you are editing is left alone, and an amber bar names the session that changed it and offers Compare (the agent's version against your text), Keep mine, and Load the agent's version. Keep mine only lets your next save replace the agent's version; Load replaces your edits. A save is checked against the version you started from, so it never silently overwrites the agent's change, with the bar read or not. A file deleted under you gets its own bar (Copy contents, Close).
- **Changes.** The top of the explorer lists what git sees as changed in the workspace: a status letter and the `+`/`−` line counts for each file, with a thin bar on the files the agent of this session touched, so you can tell its edits from changes made elsewhere. Uncommitted | Branch switches the list between the changes not yet committed and the working tree against the point where the branch left its base branch; the server finds the base branch in the repository, the browser never names it. Git is read in a locked-down container, never run on your host, because a workspace's git config is not trusted. While the agent works, the dock follows its edits: files it just touched appear at once with a "…" until git answers. A count that cannot be read is left out, not guessed. Changes is also a view of one file: the Code | Changes switch in the dock's bar, or a git badge in the tree, shows the file against HEAD (in Branch view, against the merge base) as a diff that includes your unsaved edits. It is for review; switch to Code to edit. In Code, marks in the gutter and the scrollbar show added, modified and removed lines against the same base. Where git cannot be read (no box runtime, not a repository, a file inside a box), the switch is disabled and says why. A deleted file's row opens its diff, which shows what was removed.
- **Reviewing a diff.** The diff is Side by side by default and falls back to Inline by itself when the dock is too narrow for two sides; the Inline | Side by side switch in the dock's bar overrides it. The ⋯ menu has Line numbers and Wrap diff (Alt+Z while the diff has the keyboard). Above the diff, "Change N of M" names the change you are on. F7 goes to the next change and, past the last one, to the next changed file of the session; Shift+F7 goes back, onto the last change of the previous file. Mark reviewed ticks the file off, and the Changes list then says "reviewed n of m". The mark clears by itself when the agent edits the file again, so a ticked file is one you have seen as it is now.
- **All changes.** Review, above the Changes list, or View all in a diff's header, opens every changed file of the session in one scroll, one section per file, starting at the first file you have not marked reviewed. A section loads only when it comes near the screen and lets go when it is far away, so a long list stays light. Unchanged stretches of a file are collapsed. While this tab is on screen, a click in the Changes list scrolls to that file's section. Past 100 files the tab holds the first 100; open the rest one by one from the list.
- **Image diff.** A changed image is shown as two pictures instead of text: Side by side, Swipe (the new one cut at a divider you drag), or Onion skin (the new one blended over the old by a slider). An added image shows only the new side and a deleted one only the old side, with no mode to pick. Images are drawn only through an image element, so a script inside an SVG never runs.
- **Line notes and Paste to the session.** In a diff, the gutter's "+", the selection bar's Add note, `c`, or Mod+Shift+A (Cmd+Shift+A on macOS) from Code or Changes adds a note on a line; a note can be edited or deleted. Notes follow the file while the agent edits it: a note whose line text is still there moves with it, and one whose line is gone says "outdated" and keeps its old line number. Notes are kept in this browser only, per session, never on the server; a session that ends takes its notes with it. While any note is pending, a bar over the editor reads "N notes · sent as one message". Preview shows the exact text. **Paste to <session>** puts all pending notes at the agent's prompt as one pasted block and never presses Enter: you read it, add to it if you want, and press Enter yourself. It is refused, with the reason in the button's title and a toast, while the agent is working or is waiting on you (a permission prompt, a question, a sign-in), when the session's terminal is not on screen, when the program at the prompt does not accept pasted blocks (bracketed paste is off), when a file that has notes has unsaved edits (its line numbers would not match the file on disk), and when the message would be over 16,000 characters. Nothing is queued to paste later. Control characters in a note, a quoted line or a file name are removed from the pasted text (only line breaks and tabs stay), so nothing in it can end the paste early or run as typed input. Notes that were pasted move to Sent; the Sent toggle shows them, muted, in the diff so you can check the fix against them.
- **Follow agent and the selection bar.** The Follow toggle in the dock's bar is off by default and remembered per session. While it is on, each file the agent finishes editing opens as the preview tab and scrolls to its first change against HEAD, without taking the keyboard from the terminal; it does nothing while you are typing in the editor. Select lines, or click a line number, and a bar offers **Insert at prompt** and **Copy**. Both use the absolute path as `path:a-b` (`path:N` for one line). Insert types it at the session's prompt and never presses Enter. It refuses, with a toast that says why, when the session's terminal is not on screen or the session is waiting on you to answer a card (a permission prompt, a question). That holds on the phone too, so the phone's tree and viewer no longer offer Insert path.
- **Markdown.** A markdown file opens as Preview | Source | Changes. Preview is the rendered text of your buffer, refreshed as you type; Source is the editor; Changes is the diff. Previews, in the dock and on the phone, never run scripts and never load anything from the network: a remote image becomes a "remote image blocked" placeholder that links to its address, while images that live in the workspace still draw.
- **Full mode.** The Full button gives the editor and the tree the whole pane area. The terminal folds into an agent strip at the bottom, with the session's name, its status, the agent's last action, and Show terminal; Esc leaves a Full mode you chose. When the window is too narrow for the dock beside the panes, the tree folds to a narrow icon strip first, the panes shrink toward a minimum width, and only then does the dock open in Full mode on its own. A reload does not reopen the dock in that case, so it never brings the terminals back covered. The strip's Insert at prompt, like the selection bar's Insert in Full mode, leaves Full mode first and then types at the prompt that is now on screen. Mobile keeps today's viewer, in its own pane, with its Edit button. Two things changed there: its markdown preview follows the same no-scripts, nothing-remote rule, and it no longer offers Insert path, because its terminal is never on screen beside the file.

## Contain

- **Boxed runtime (the default).** Each project gets its own Docker container: only the project directory is mounted writable, with no host home, no `~/.ssh`, no Docker socket and no inherited daemon environment. The container runs as your uid, drops all capabilities, sets `no-new-privileges`, uses a read-only root filesystem, and has a PID limit and a memory cap (`box_memory`). Idle boxes are removed after a timeout. A box's home stays on the host for 30 days after its last use, so its login and resume history survive; the regenerable caches in it (Go build and module caches, the npm cache, a plugin's Python venv) are dropped about an hour after its last use. A `host` tier (no containment) exists for work that needs the machine, and you choose it explicitly.
- **macOS.** Boxes run in CuliBox's own [colima](https://github.com/abiosoft/colima) VM, separate from any Docker setup you already have. See [docs/MACOS.md](MACOS.md).
- **Config bundle.** A boxed session gets an allowlisted slice of your agent configuration (`CLAUDE.md`, skills, agents, commands, a filtered `settings.json`, and MCP servers that can run inside the image). Credentials, history and transcripts are never copied. Your Claude Code plugins come along as a read-only, git-free copy. If any part of the plugin set is a symlink, or a marketplace URL in it carries credentials, the whole set is left out and recorded as a drop. The box image can declare its own MCP servers in `/etc/agent-box/mcp.json`; they replace same-named servers from your config, and each replacement is recorded as a drop. The image ships Chromium and the Playwright MCP server (`playwright`), which writes its output to `/tmp/playwright-mcp`. The files your `CLAUDE.md` `@`-imports come along too, read-only; this is on by default and off per profile with `imports_off` (see [CLAUDE.md imports](CLAUDE-MD-IMPORTS.md)). On Linux, a bundle with its copy of the imports, and a plugin copy, are removed once no container, running or stopped, mounts them and no spawn has used them for 14 days. On macOS nothing is removed automatically.
- **No AI attribution in box commits.** Claude Code inside a box never adds a `Co-Authored-By` trailer or a "Generated with" line to commits or pull requests, whatever your own settings say. The box image sets this as Claude Code policy, and the config bundle repeats it.
- **Box shell.** A boxed shell profile whose shell is missing in the image (a Mac's quick shell is `$SHELL`, for example `/opt/homebrew/bin/zsh`) runs the image's shell of the same name, or else `/bin/bash` with a notice. Agent binaries never fall back. The image ships zsh with history search (fzf: Ctrl-R, Ctrl-T, Alt-C), autosuggestions, syntax highlighting, and completion for aws, terraform, kubectl (`k`), helm, stern, yq and gh. Its prompt shows the time, `box`, the directory, and only the context that is set: git branch, AWS profile and region, kube context and namespace, a non-default terraform workspace, and how long a slow command took. A value that looks like production (`prod`, `prd`, `production`, `live`) is shown in red. Defaults live in `/etc/agent-box/zshrc`; your own `~/.zshrc` loads after it. `ping`, `mtr`, `traceroute`, `tracepath` and `httping` are not installed. On Linux a box reaches the internet only through the HTTPS proxy, so these would measure the fence, not the target. Each name is a stand-in that says so and exits 127. Diagnose the network on the target or from a host-tier profile. `ipcalc`, `tree`, `file`, `bc` and `nano` work offline.
- **Multiple accounts.** Run sessions under named agent accounts, each with its own config directory and its own token, kept apart from your personal login. Only Claude accounts can launch sessions. An account signs in either with **Log in** (an interactive `/login`) or with a long-lived token from `claude setup-token`, pasted on its row in Settings → Agent accounts. The token is kept in the encrypted store under `ACCT_<NAME>_TOKEN` and injected as `CLAUDE_CODE_OAUTH_TOKEN`, and Claude Code prefers it over a `/login` login. Such a token lasts one year and only makes model requests (no claude.ai connectors or Remote Control). Remove token unlinks it and deletes that stored value. Quota meters appear after the first session under the account.

## Cloud access, audit and secrets

- **AWS credential broker.** Define an AWS connection in Settings › Credentials and tick it on a boxed profile. The host mints 15-minute credentials by assuming a read-only IAM role from your own SSO session, with an inline session policy that narrows the role further (see [Security model](SECURITY.md)). The box never sees your SSO session. Credentials reach the AWS CLI and Terraform inside the box through `credential_process`. A profile can bind several connections, so one session reaches several accounts (see [Several AWS accounts in one session](AWS.md#several-aws-accounts-in-one-session)). Where you cannot create that role, a connection can opt in to using a read-only SSO permission set directly, behind a read-only gate (see [SSO role directly](AWS.md#sso-role-directly-opt-in)).
- **GitHub access.** Define a GitHub App in Settings › Credentials and bind it to a boxed profile. The broker mints one-hour GitHub App installation tokens scoped to the repos you list, read-only by default, with write on contents, pull requests and issues if you allow it; `git` and `gh` in the box use them, and the box never holds a personal access token unless you bind one (see [GitHub access for agents](GITHUB.md)).
- **The agent knows what it has.** A boxed Claude session is told at start which AWS profiles, GitHub owners and tokens it holds, which are PROD and how to use each, never a value. `agentbox-env --list` inside the box shows the details.
- **Attribution and audit.** Credentials are minted with `SourceIdentity` and role session name `agentbox-<session id>`, so CloudTrail records the agent session rather than you (not in the opt-in [SSO-direct mode](AWS.md#sso-role-directly-opt-in), where CloudTrail shows you). The broker also writes every mint, refusal and failure to a local SQLite audit log, with no credential values in it.
- **Secrets by reference.** A credential entry names where its value lives (a file, an environment variable of the daemon, or the encrypted store) rather than containing it. The value is read when it is needed, handed only to the profiles bound to that entry, and never logged.
- **Encrypted value store.** A small encrypted store in the data root holds tokens, a GitHub App key or the Claude token as ciphertext, so a disk snapshot or backup does not expose what you keep in it (see [Store](STORE.md)).
- **`culibox doctor`.** Checks the machine and prints PASS, WARN or FAIL lines. It is read-only and prints no secrets, so the output is safe to paste into an issue.
