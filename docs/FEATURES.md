# Features

Every feature in detail. The [README](../README.md) has the one-line summary.

## Watch

- **Multi-session web terminal.** Run several agent sessions side by side in the browser (xterm.js over WebSocket), on desktop or phone. A plain drag over Claude Code's fullscreen view copies the text: the agent's clipboard write (OSC 52) is accepted only within 1.5 seconds of you releasing a click or drag, or pressing Ctrl+C, in that terminal, while it is visible and focused, and never while the session's earlier output is still being replayed after a reconnect. Each copy shows a toast with the number of lines. Text with a bare carriage return, a line or paragraph separator, or a Unicode format character (text-direction controls, zero-width spaces and joiners, tag characters) is refused with a warning, because pasted into a shell it could run something the screen never showed; Shift+drag (Option+drag on macOS) still copies it, emoji sequences joined by a zero-width joiner included. A request to read your clipboard is never answered. Shift+drag (Option+drag on macOS) still selects with the terminal's own selection.
- **Attention awareness.** Sessions report whether they are working, idle or waiting, and why: a pending tool call or permission prompt, or simply your turn. The tab title and favicon change while something needs you. For Claude Code sessions, a card shows the pending tool call.
- **Usage and cost.** Per-session context size and model, and account-level 5-hour and 7-day rate-limit windows when a statusLine hook provides them. A local analytics store (SQLite) ingests Claude Code transcripts into daily token usage, estimated cost per model, project and session, and skill/MCP attribution. Dollar figures are estimates from a built-in price table. Analytics can be turned off.
- **Environment badge.** `env_label` and `env_color` mark an instance as DEV, PROD and so on in the UI.

## Run and steer

- **Session persistence.** Agents run under [abduco](https://www.brain-dump.org/projects/abduco/), so they survive a restart of the CuliBox daemon. On restart, CuliBox re-attaches. Closing the browser or the terminal that runs `agent-box serve` does not kill sessions.
- **Steer from the UI.** Interrupt a session, restart an exited one (Claude Code sessions on the host tier resume the same conversation), and, if `"replies_enabled": true` is set in config.json (off by default; restart to apply), answer permission prompts or send a one-line reply from the needs-you card. This is limited to Claude Code sessions.
- **Profiles.** Agents are defined in the config file or created at runtime in the UI, with launch options (flags and env vars) as toggles on the spawn form. A quick-shell profile is detected from `$SHELL`. A save made from a stale editor is refused, so an older tab or another device cannot overwrite a newer change.
- **Files.** Browse, search, view, edit, upload, and download folders as an archive, with size and file-count caps.

## Contain

- **Boxed runtime (the default).** Each project gets its own Docker container: only the project directory is mounted writable, with no host home, no `~/.ssh`, no Docker socket and no inherited daemon environment. The container runs as your uid, drops all capabilities, sets `no-new-privileges`, uses a read-only root filesystem, and has a PID limit and a memory cap (`box_memory`). Idle boxes are removed after a timeout. A `host` tier (no containment) exists for work that needs the machine, and you choose it explicitly.
- **macOS.** Boxes run in CuliBox's own [colima](https://github.com/abiosoft/colima) VM, separate from any Docker setup you already have. See [docs/MACOS.md](MACOS.md).
- **Config bundle.** A boxed session gets an allowlisted slice of your agent configuration (`CLAUDE.md`, skills, agents, commands, a filtered `settings.json`, and MCP servers that can run inside the image). Credentials, history and transcripts are never copied. Your Claude Code plugins come along as a read-only, git-free copy. If any part of the plugin set is a symlink, or a marketplace URL in it carries credentials, the whole set is left out and recorded as a drop. The box image can declare its own MCP servers in `/etc/agent-box/mcp.json`; they replace same-named servers from your config, and each replacement is recorded as a drop. The image ships Chromium and the Playwright MCP server (`playwright`), which writes its output to `/tmp/playwright-mcp`. The files your `CLAUDE.md` `@`-imports come along too, read-only; this is on by default and off per profile with `imports_off` (see [CLAUDE.md imports](CLAUDE-MD-IMPORTS.md)). On Linux, a bundle with its copy of the imports, and a plugin copy, are removed once no container, running or stopped, mounts them and no spawn has used them for 14 days. On macOS nothing is removed yet.
- **Box shell.** A boxed shell profile whose shell is missing in the image (a Mac's quick shell is `$SHELL`, for example `/opt/homebrew/bin/zsh`) runs the image's shell of the same name, or else `/bin/bash` with a notice. Agent binaries never fall back. The image ships zsh with history search (fzf: Ctrl-R, Ctrl-T, Alt-C), autosuggestions, syntax highlighting, and completion for aws, terraform, kubectl (`k`), helm, stern, yq and gh. Its prompt shows the time, `box`, the directory, and only the context that is set: git branch, AWS profile and region, kube context and namespace, a non-default terraform workspace, and how long a slow command took. A value that looks like production (`prod`, `prd`, `production`, `live`) is shown in red. Defaults live in `/etc/agent-box/zshrc`; your own `~/.zshrc` loads after it. `ping`, `mtr`, `traceroute`, `tracepath` and `httping` are not installed. On Linux a box reaches the internet only through the HTTPS proxy, so these would measure the fence, not the target. Each name is a stand-in that says so and exits 127. Diagnose the network on the target or from a host-tier profile. `ipcalc`, `tree`, `file`, `bc` and `nano` work offline.
- **Multiple accounts.** Run sessions under named agent accounts, each with its own config directory and its own token, kept apart from your personal login. Only Claude accounts can launch sessions. An account signs in either with **Log in** (an interactive `/login`) or with a long-lived token from `claude setup-token`, pasted on its row in Settings → Agent accounts. The token is kept in the encrypted store under `ACCT_<NAME>_TOKEN` and injected as `CLAUDE_CODE_OAUTH_TOKEN`; it needs no `secret_sources` entry, and Claude Code prefers it over a `/login` login. Such a token lasts one year and only makes model requests (no claude.ai connectors or Remote Control). Remove token unlinks it and deletes that stored value. Quota meters appear after the first session under the account.

## Cloud access, audit and secrets

- **AWS credential broker.** A boxed profile can carry an `aws` binding. The host mints 15-minute credentials by assuming a read-only IAM role from your own SSO session, with an inline session policy that narrows the role further (see [Security model](SECURITY.md)). The box never sees your SSO session. Credentials reach the AWS CLI and Terraform inside the box through `credential_process`. A profile can instead bind several named AWS connections (see [Several AWS accounts in one session](AWS.md#several-aws-accounts-in-one-session)). Where you cannot create that role, a binding can opt in to using a read-only SSO permission set directly, behind a read-only gate (see [SSO role directly](AWS.md#sso-role-directly-opt-in)).
- **GitHub access.** A boxed profile can carry a `github` binding. The broker mints one-hour GitHub App installation tokens scoped to the repos you list, read-only by default, with write on contents, pull requests and issues if you allow it; `git` and `gh` in the box use them, and the box never holds a personal access token unless you bind one (see [GitHub access for agents](GITHUB.md)).
- **Attribution and audit.** Credentials are minted with `SourceIdentity` and role session name `agentbox-<session id>`, so CloudTrail records the agent session rather than you (not in the opt-in [SSO-direct mode](AWS.md#sso-role-directly-opt-in), where CloudTrail shows you). The broker also writes every mint, refusal and failure to a local SQLite audit log, with no credential values in it.
- **Secrets by reference.** Config names secrets rather than containing them. Values are resolved at spawn time from the environment, a file or the encrypted store, injected only into the agent that declares them, and never logged.
- **Encrypted value store.** A small encrypted store in the data root holds tokens, a GitHub App key or the Claude token as ciphertext, so a disk snapshot or backup does not expose what you keep in it (see [Store](STORE.md)).
- **`agent-box doctor`.** Checks the machine and prints PASS, WARN or FAIL lines. It is read-only and prints no secrets, so the output is safe to paste into an issue.
